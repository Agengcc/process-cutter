# 分级审片和批量执行

目标：维持真实画面判断和完整动作，减少无必要的图片、模型往返及长历史。采样只负责提供画面，脚本不判气口、不写“已看片确认”。

本页的审片密度为标准模式默认值。精剪先读[精剪模式](fine-cut.md)，以其制作段首尾、细节过程和成片细节复核要求为准；本页批量、缓存和控制历史的方法继续适用。

## 处理一组素材

1. 一次列出素材和生成1fps总览；每组处理2–3个相关源文件，实际打开该组所有总览分页。先辨认主体、所有可见工序、候选段，不能只看首个工序。
2. 对已确定范围的窗口，写一个JSON任务数组，执行一次批量抽帧。普通作业3fps，展示1–2fps；眼睛高光、细线、撒料等小变化直接10fps局部图。全景总览确认身份和构图，局部图确认细节，不再把同一处小细节全景和局部整段都抽10fps。
3. 宿主支持同一轮调用多个Read/图片工具时，一轮实际打开2–4张相关分页；按时间标签分别判断，不能把生成列表算打开。不支持时逐张读，不编造批量已读。
4. 看完全部候选分页后，确认操作前、制作变化、完成态和短衔接。普通段仍有疑点时，只对疑点和必要边界补10fps；仍不清楚才短窗源帧率。看不清微小结果时必须补图，不能为了速度跳过。
5. 这一组一次保存选片表和短索引，确认前后状态接得上，然后下一组。记录素材文件、选/不选、已确认范围、图片路径、剩余文件和疑点即可；不逐帧描述方向、次数和故事，不重复抄规则。

JSON任务示例（使用实际绝对路径，不使用占位文字执行）：

```json
[
  {"video":"/项目/日期/原片1.MOV","start":4,"end":10,"output":"/项目/日期/edit/本次版本/review/source/01_action.jpg","fps":3},
  {"video":"/项目/日期/原片2.MOV","start":5,"end":8,"output":"/项目/日期/edit/本次版本/review/source/02_eye.jpg","fps":10,"crop":[0.2,0.3,0.4,0.3]}
]
```

```bash
python3 "$SKILL/scripts/motion_cut_helper.py" --batch "$OUT/review/source/本组抽帧任务.json"
```

抽帧器按源文件路径、大小、修改时间、窗口、fps、裁剪、生成器版本及各页状态校验缓存。同参数且图片完整时免重抽；图片缺失或更改则重抽。读取结果中的`pages`，不要通配读取同目录旧页。缓存命中只证明图未变，当前会话依旧要实际读图；不继承其他会话的“已看片确认”。

## 控制往返与历史

- 工具路径和用法已在手册，不例行读取每个脚本全文、反复`--help`或逐素材重新检查工具。确有错误再定位。
- 每轮读图只输出一份短判断：主体/工序、候选范围、是否补图。一次填完本组记录；不为每张图另写长解释或重写整个索引。
- 宿主提供明确的上下文压缩功能时，在主体板块完成并保存后按需压缩；保留目录、主体映射、CSV/索引路径、已完成/剩余、未解疑点。不凭空调用不存在的工具，不把“继续”当新上下文，也不让用户手动多次发接续词成为默认流程。
- 已确定的片段和工具步骤不重复分析。读图已确认的同素材样段可核验后沿用；新素材或切点改变必须重新看片。
- 完成选片先用build做静态检查，通过后导出一次正式文件；只有实际缺陷才重导。不例行渲染每个样段、额外预览或全片对比版。
- 成片首尾和所有剪接点继续10fps复核；对有疑点的内部区间补看。能够连续观看时看全片，不能时如实说明，用户验收单独记录。
- 接口超时/服务端报错由宿主重试策略控制，Skill无法取消已经发生的内部等待。恢复后从已保存组继续；终止报错时保存进度和准确错误，不重跑全部素材、不换模型冒充完成。

## 下一次验证

选一个尚未剪过的日期，从一句日期提示完成全片；记录总耗时、实际读图页数、模型往返和服务报错。比较动作完整性、长停顿、身份顺序、构图与用户接受程度。先验证一次新素材整片，再确认长期默认效果；图片数量减少不能直接换算整片加速倍数。
