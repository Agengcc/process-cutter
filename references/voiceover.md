# 配音档案：画面剪辑＋API配音

用户要旁白／配音时读本页。前提：画面已剪好，用户看过选片对照图并接受。来源：2026-10-24—26 葱姜鸡六轮测试（Codex剪画面，千问复刻音色配音）。

skill 不内置任何密钥或音色。配音命令有两种来源：

- **火山（豆包）**：自带 `scripts/tts_volcengine.py`。用户在火山控制台开通豆包语音合成，把密钥设为环境变量 `VOLC_TTS_API_KEY`（新版控制台；旧版用 `VOLC_TTS_APP_ID`＋`VOLC_TTS_ACCESS_KEY`），或写进 `~/.config/process-cutter/volcengine.json`；音色在控制台音色列表里选。命令模板：
  `python3 "$SKILL/scripts/tts_volcengine.py" --text-file {text} --out {out} --words-out {words} --voice 音色ID`
  `--words-out {words}` 让火山顺带返回逐字时间（WebSocket 方式），字幕按真实开口时刻换行；HTTP 方式和其他服务没有这一项时字幕按字数估算。
  先用 `--dry-run` 看请求是否正确（不调用、不显示密钥）。语速用 `--speech-rate`（-50～100，0为正常）。
  默认走 WebSocket 双向流式接口；报 “requested resource not granted” 时，先按提示到控制台开通语音合成，或用 `--protocol http` 换 HTTP 接口试（同一密钥两个接口的授权可能不同）。
- **其他服务或自己的脚本**（千问、MiniMax 等）：只要能“读文案文件、写音频文件”，就能填进 `--cmd`。

没有配音命令也不录音时，交静音版＋选曲说明，不硬做。

## 1. 先做事实卡（不编造）

旁白要说画面说不出的东西：为什么这么做、窍门、口感和现场感受。这些只能来自事实，不能编。

- **来源优先级**：①原声里做的人自己说的（有讲话时；已有转写就直接读，没有转写要先征得用户同意再跑——本机Whisper较吃电脑）；②画面里看得见的；③用户补充。上网搜索只作“通用说法”建议，用户勾选后才能用。
- **事实卡最前面只放三样**，用户一分钟能看完：
  1. 可用事实（每条一句，注明出自哪段素材第几秒或“画面可见”）；
  2. 最多3–5个问题，每个附上你的猜测，让用户勾选或改；
  3. 旁白口吻：做的人第一人称（“我先把鸡块腌一下”）还是旁观者（“鸡块先腌一下”）。
  详细出处表放在后面备查。
- 涉及家人、伴侣、身份等私人关系的话，问用户要不要用，默认不用。
- 转写会有错字（“水电”＝水淀粉、“大姜”＝生姜）；拿不准的标出来交用户，不自己定。

葱姜鸡例子：原声里有“倒点油……主要是为了炒的时候它不那么干”“姜要煸的时间比较长，葱不能煸太久，所以先煸葱再煸姜”，正好是旁白需要的理由；黄色丁状配料也由原声确认是生姜。

## 2. 量语速

用一句约20字的文案调用配音命令生成一次，`python3 "$SKILL/scripts/voice_tools.py" rate 测速.wav "那句文案" --voice 音色ID --save` 得到实测字/秒，并记到本机 `~/.config/process-cutter/voices.json`（不进仓库）。之后所有字数上限按实测值算，不用估计值。同一音色已经量过就不用再量，`limits` 用 `--voice 音色ID` 直接读；换了 `--speech-rate` 算另一条，要重新量（合成和量时都带上同样的 `--speech-rate`）。不同音色语速差别很大（猴哥明显比千问复刻慢），换音色必须先量。

## 3. 写配音脚本，先给用户确认

`配音脚本.csv` 列：`句号,成片起秒,成片止秒,文案,对应画面`。写完运行 `voice_tools.py limits 配音脚本.csv --voice 音色ID`（或 `--rate 实测值`），自动补上可用秒数、字数上限（窗口×字/秒×0.85）和建议字数（上限的80–100%，即配音约占窗口70–85%，暂定），并列出超字、字太少和窗口过长（超过约6秒）的句子。

写稿规则：

> **下面带数字的节奏值都是暂定**：配音占窗口70–85%、句间空档<1秒、留白（无垫底<3秒、有垫底<5秒）、全片配音占40–65%，全部只来自葱姜鸡v6一个样本（做饭、讲解价值高的工序多）。讲解少、动作本身就好看的段落，配音占比可以更低，用配乐垫底；以用户听感为准，交付时写明实际占比。等第二条做饭视频的配音被用户认可后，再把数值改成正式规则；只有一个样本时不改。

- **一句一个完整短句，各自合成；合成好的句子一律不切开。**要对齐动作就在写稿时拆，不在音频上拆。（v1教训：把一段合成好的话在停顿处切成四截分散摆放，语调被切断，中间空2–3秒，听起来断断续续。）
- **连续的小动作合成一句**，不要逐镜头报幕。“先倒生抽。再加生粉。用手抓匀。”→“鸡块先加生抽和生粉，用手抓匀。”（v2教训：22句逐个描述画面，观众本来就看得见，听起来像报菜谱。）
- **说画面说不出的**：理由、窍门、感受，只用事实卡里确认过的。看得见的动作一笔带过。
- 开头一句配成品画面，说出最吸引人的点（菜名＋最香／最难／最有意思的地方）。
- **每句都要带信息或必要的提示**：理由、窍门、感受，或者阶段切换（“接下来调碗汁”）。**带标准、窍门或顺序的动作描述也算信息**，要说：“大葱切成大段就行，不用切太细”“煸到表面有点焦黄就盛出来”“姜煸好了，葱和鸡块再回锅”。只有纯动作（“挤入一点蚝油”“把汁倒进去”）不说——那里**留白**，脚本里写一行“（留白）”，不合成。
- **留白要有东西垫着**：有配乐或现场声时才能留几秒；什么都没有时（静音画面＋配音），留白不超过约3秒（暂定）。有垫底时单段留白一般也不超过约5秒（暂定），再长就补一句阶段提示或标准。
- **开口就说满，不开口就留白**：说的那句字数落在建议字数里（配音约占窗口70–85%，暂定）；同一段连续讲解里句间空档一般不超过1秒（暂定），一段讲完可以留几秒空白。窗口超过约6秒、又有不止一条信息时，在动作切换处拆两句；只有一条信息时，这句放在窗口开头，窗口改短到这句话的长度，剩下的另起一行“（留白）”。全片配音一般占40–65%（暂定，来自葱姜鸡v6；讲解少的片子可以更低）。
- （v5教训：只在“理由”处开口，把“切大段就行”这类带标准的话也删了；全片配音只占34%，又没有配乐和现场声，中间5–12秒的无声听起来像卡住。）
- （v3教训：曾写成“上限的60–80%”，配音只占窗口一半，长窗口后面空5秒。v4教训：又要求“每个窗口都说满”，信息不够时就拆出“接着挤入一点蚝油”“剩下的碗汁也倒进去”这类报幕句。）
- 开头用已确认的窍门或最大的看点，不用负面或没确认的经历开场（如“上次偏咸”，说话人也没确认）。
- 删掉“提前放在一起，等会儿再用”“调料还没加完”这类不带信息的话。
- 补句时先看前后句有没有说过同一件事，不要两句重复同一信息（v6：“最后加水淀粉搅匀”和补的“水淀粉倒进去以后，用勺子把碗汁搅匀”重复了）。`voice_tools.py limits` 会列出相邻或隔一句共享词语的句子（“可能重复”），只是提醒：同一食材在不同步骤出现是正常的，逐条判断后再改。
- 口语、短句；避开多音字、生僻词、读起来拗口的数字；不写“AI味”的抒情句，不写“调料还没加完”这类凑字数的话。
- **写完停下，把脚本发给用户确认**，确认后再合成。

## 4. 逐句合成、量时长

```bash
python3 "$SKILL/scripts/voice_tools.py" synth "$OUT/配音脚本.csv" "$OUT/配音" --cmd '用户的配音命令 {text} {out}'
```

- 每句单独调用一次；已合成且文案没变的句子不会重复调用（省钱）。
- 合成时长超出窗口15%以内：自动不变调加快（最多1.15倍）。超出更多：标“需改短”并退出，改那几句文案后用 `--only 3,7` 只重做这几句；仍放不下就在交付说明里建议延长哪个镜头，不擅自改画面。
- `配音/时长核对.md` 会列出每句占窗口比例和超过1秒的句间空档。占比低于约60%的句子说明写短了，补理由或感受，不要拆句子凑。
- 配音命令失败就停下看输出，不自动反复重试（每次调用都可能计费）。

## 5. 出片

```bash
python3 "$SKILL/scripts/cutter.py" render --project "$OUT/project.json" --output "$OUT/含配音版.mp4" --voice "$OUT/配音/配音表.csv" [--music 配乐] [--source-audio]
```

- 每句整段放在它的成片起秒；句子重叠或超出成片结尾会报错。
- 字幕直接用配音文案，按标点断成每行不超过14字，时间按字数分配到这句配音里（不做逐字对齐）。
- 有配乐或现场声时，它们在配音出现时自动压低。配音版的配乐整体再降约12–15 dB（`--music-gain -13`），否则旁白间歇时音乐太冲。
- 葱姜鸡v6（2026-10-26，用户认可）可作参照：80秒成片13句、配音占46%，配乐垫底，留白基本不超过5秒；只在有理由、窍门、标准或顺序的地方开口。

## 6. 检查与交付

- 交付说明写：事实卡链接、用户确认过的口吻、配音调用次数、需改短重做了几句、时长核对表。
- 请用户**连续听一遍**：对不对得上画面、有没有读错字和多音字、是不是断断续续或念个不停、有没有说出事实卡以外的东西。
- 可选：`final_check.py` 从成片里转写每句配音核对吞字（本机跑Whisper，开启前说明耗时并征得同意）。
- 声音授权：只用自己有权使用的声音；不要用某个真人的复刻声音替他说没说过的话（替换原声里的句子用明显的角色音，见做饭档案）。发布时提醒打开平台的AI生成声明。仓库和交付文件里不写任何密钥。
