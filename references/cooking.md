# 做饭档案：有人讲解的做饭视频

题材是做饭、素材里有人讲话时读本页。来源：2026-10-17 用拉面素材（13段、4.7分钟→119秒成片）实剪一次。本页补充主手册；真实看画面、选片表、构建与三层检查照主手册。其他题材素材里有人讲解时，讲话处理也参照本页。

## 1. 讲解是主线

- 用户默认要“讲解为主”：做饭的人边做边讲，拍的人偶尔提问。有信息或有生活感的问答保留（例：“为什么不等水开就放菜？”“谁喜欢？”“你！”）。
- 有人说话的段落标`讲解`，**速度1.0**，整句保留，只在句与句的停顿里下刀。超过约0.7秒的句间停顿剪掉；同一镜头内跳剪可以接受。
- 没人说话的操作段标`制作`，按画面变化加速（2–2.5倍常用），现场声随之变速不变调。
- 加速段里如果有零星说话，听不清就不配字幕；能听清又有用的，拆出来按讲解处理。

## 2. 先找声音，再找画面

**AI听不到声音**，现场讲话的取舍最后都要人确认。

**原声模式是可选项，默认关闭。**它要在本机跑Whisper：第一次下载约1.6GB模型；苹果M系列芯片上拉面13段要几分钟、风扇会转；Intel Mac或Windows只能用普通方式跑，会慢很多。只有用户明确要保留现场讲话时才开，开之前先告诉用户会比较吃电脑、耗时间，得到同意再跑。

开启后先出原声清单，不让模型凭转写自己决定剪哪句：

```bash
uv run --python 3.13 --with mlx-whisper --with zhconv --with numpy \
  python3 "$SKILL/scripts/speech_takes.py" "$DAY" "$OUT/原声清单" --rnn 降噪模型.rnnn
```

- 方法借自 vincentventalon/claude-code-video-editing-skill 与 TinyAlmond/footage-to-vlog（均MIT）：按静音切成小岛逐个转写，只在静音处下刀；每个小岛错开时间再转写两次，三次里两次一致才算真话（噪声会变成不同的字）；Whisper常编的套话（“请不吝点赞订阅”等）直接去掉。
- 清单状态：`建议删`（说了一半重来、只有语气词、拍摄沟通）、`选一遍`（两遍都说完整了，默认留后一遍，但要用户听后选——拉面开头用户选的是中间那遍）、`待听`（句内重复，没有静音可下刀）、`不稳`（多半是噪声，画面里在说话就请听）、`留`。
- **覆盖低于85%的素材，切点不可靠**：有话被当成静音（油烟机底噪下常见，拉面8266、8269、8272都是），这些素材只能人工听着定切点，不按小岛下刀。
- 清单交用户确认后才写进选片表。拿不准的一律保留并标出，不猜。

其余线索照下面做：

1. 每段素材做两路转写：Whisper（`word_timestamps`，给时间）和第二个模型（如 Qwen3-ASR，中文文字通常更准）。转写是**线索**：沸水、油锅声会被识别成“好”“okay”“鸡鸡鸡”之类的重复，必须对照波形排除。
2. 用 `scripts/audio_review.py` 出人声频段波形图（自动按本段底噪定阈值），把转写字词标在时间轴上，确定每句的起止和句间停顿。
3. 再按主手册抽帧看画面，确认讲解对应的动作、加速段的起止状态。

## 3. 必须剪掉的

- **重录**：“声音大一点，再来一遍”、同一句说两三遍时，只留最后一遍完整的。
- **口误后的更正**：留更正后的说法，口误整句去掉（例：“把泡面放在最底层”→“把蔬菜放最底层”）。
- **拍摄沟通**：“你要走近那点”“我要说啥来着”“不要讲这个，我要先说开头”“讲解一下”。
- **说错事实的开场**：例如口播菜名和实际包装不符，就不用那一条，改用说对的一遍。

### 句内卡壳与稀碎段（2026-10-23 加）

上面几条处理的是整句；一句话内部的问题按下面分三档，先列成清单给用户确认，再动手：

| 档 | 例子 | 处理 |
|---|---|---|
| 剪掉 | 动作时的长时间沉默（超过约0.7秒）、句中“嗯/呃”、同一个词连说两遍 | 沉默段改成加速制作段或剪短；词级重复只在字词边界下刀，听起来不顺就保留 |
| 配音替换 | 同一个意思绕来绕去、重复多遍、逻辑乱，剪哪里都不通（例：拉面里“500毫升”一段说了五遍） | 写一句改写文案（意思不变、更短），由用户选角色音生成音频；原句的人声去掉，现场声压低垫底，字幕改成新文案 |
| 保留 | 对话里被打断、抢话、笑场等有生活感的地方（例：“因为我们喜欢把那个……”“谁喜欢？”“你！”） | 不动；这是做饭视频的味道，不是卡壳 |

- 找法：逐字转写里看连续重复的词和字词间超过约0.5秒的空档；Whisper常把“嗯/呃”略掉，波形上有人声而转写没字的位置就是。多路转写对照，拿不准的标“待听”交用户。
- 配音用**明显的角色音**，让观众知道是后期配的；不要用说话人本人的复刻声音替他说没说过的话。画面里看得见嘴型时，换到不露嘴的画面。
- 配音音频由用户提供，放进项目的`配音/`文件夹并在选片表里注明替换的源区间；语速偏慢时用只变速不变调的方式加快（拉面案例用1.5倍）。发布时提醒打开平台AI生成声明。

### 油烟机等持续底噪（2026-10-23 加）

- 普通频谱降噪（afftdn）对油烟机几乎无效；用FFmpeg自带的RNNoise人声降噪：`arnndn=m=<模型>.rnnn:mix=0.75,highpass=f=70`，再补约6 dB使人声回到原来的响度。模型可用 richardpl/arnndn-models 的 `sh.rnnn`（约87KB），放在项目里或由用户提供。
- 先截一段有人声、有锅声的20秒左右片段，出轻（mix 0.5）、中（0.75）、重（1.0）三档给用户试听再定。拉面案例选“中”：重档会让人声跑偏，锅声也被压掉。
- 降噪只生成项目内的副本（`降噪源/`，视频流直接复制、只换音轨），用副本做`build --media-dir`；原素材只读。
- 有BGM时底噪会被盖住一部分，可以降得更轻。

## 4. 字幕

- 字幕文字取三路转写的多数：整段 Qwen、整段 Whisper、按窗口单独转写（短窗口最不稳，只作参考）。三路仍不一致的，按上下文选一个，**在交付说明里列为待确认**，不能写成已核对。
- 每行一句、不超过两行（约14字一行）；字幕表写源时间：`源文件,源起秒,源止秒,文字`。
- 定时：`scripts/caption_align.py 字幕行.json 素材目录 字幕表.csv --words-dir 逐字目录`。它按逐字时间找锚点、对不上再按字数比例，并在每行最后一段发声后0.3秒收掉。**同一词反复出现（如三次“500毫升”）时锚点会错**，要按波形手改。
- 渲染：`cutter.py render --source-audio --captions 字幕表.csv`；成片旁会生成`.字幕时间.json`（含每句的源时间）。

### 成片逐句核对（可选，默认关闭）

与原声模式一样要本机跑Whisper，开启前同样先说明耗时、征得同意。用户没开时，交付说明写“逐句核对未做”，提醒用户自己重点听讲话段。

借鉴 footage-to-vlog 的 finish --verify：从成片里把每句重新转写，和字幕比对；同一句也在原素材里转写一次作对照。原声和配音句都适用。

```bash
uv run --python 3.13 --with mlx-whisper --with zhconv --with numpy --with pillow \
  python3 "$SKILL/scripts/final_check.py" "$OUT/成片.mp4"
```

- 报告`成片.逐句核对.md`分两档：**先听**＝原素材听得出、成片听不出（切到字、被混音盖住）；**再听**＝原素材这里也没听出（字幕多写了没说的字、选错了那一遍，或环境太吵）。
- 拉面v3验证（40句，先听6句、再听11句）：开头“豪华版不倒翁拉面”在“再听”，缺“拉面”——原素材那一遍就没说全，即选错了一遍；“好，现在已经开了”“鸡蛋已经有点开始变白了”“放在面饼上的鸡蛋”等在“先听”，入点切到了字。嘈杂素材上“再听”一档会偏多。转写固定 temperature=0，同一成片每次结果一致。
- 交付说明附这份报告，请用户**按报告重点听**；“听得出”只说明Whisper听得出，不等于人耳满意，不能写成已听审。

## 5. 结构

- 开头由Agent按素材判断（主手册“开头”一节）：有更抓人的变化瞬间时（如掀开锅盖“哇，太阳蛋”），用它的1–3秒开场；否则用成品＋说对的菜名一句（约2–3秒）。交付说明写清用了哪个、备选是什么，用户可换。没有成品照片时不做0.2秒封面占位。
- 中段按真实工序推进；等待（腌、焖、煮）用前后两个状态直接接，不保留空等。
- 结尾：成品全貌、包装或上桌，约5–7秒，可轻加速。
- 时长由讲解决定；本次119秒。

## 6. 声音

- 剪接点已自动做20毫秒淡入淡出；仍要连续听一遍有没有突兀的音量跳变。
- 给了 BGM 时用 `--music`，与现场声同时存在会自动避让人声。
- 本次成片约 -20 LUFS（未做响度标准化），发布前按平台习惯再调。
